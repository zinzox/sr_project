Presentation du projet Sarbi Rohek

Plateforme de mise en relation entre clients et prestataires, avec une experience separee pour chaque role (client, prestataire, admin), un systeme d'authentification et des interactions en temps reel via messagerie.

Projet: Sarbi Rohek

Objectifs et valeur du projet

Probleme cible

Difficulte a trouver des prestataires fiables rapidement et a gerer les echanges dans une interface unique.

Solution proposee

Un portail simple avec recherche de prestataires, profils verifies, espaces dedies par role et messagerie.

Resultat attendu

Ameliorer la confiance, gagner du temps et structurer la relation client-prestataire avec un suivi clair.

Comment j'ai realise le projet

1. Analyse et decoupage

J'ai decoupe le besoin en modules: authentification, gestion des profils, espaces par role et messagerie. Chaque module a ete developpe de facon iterative pour garder une progression mesurable.

2. Implementation progressive

J'ai commence par une version minimale fonctionnelle, puis j'ai ajoute les features une par une, en validant chaque etape avant de passer a la suivante.

3. Liens Frontend/Backend

Les pages JavaScript appellent des servlets dedies pour verifier les comptes, recuperer les donnees et alimenter les vues client/prestataire/admin.

4. Verification et amelioration

A chaque iteration, j'ai teste les parcours principaux (inscription, connexion, navigation, messages), puis j'ai corrige les points bloquants et ameliore l'interface.

Tomcat, MySQL et connexion entre les deux

Ou se trouve la base

La base s'appelle sarbi_rohek et tourne sur MySQL local (localhost:3306). Les donnees physiques sont stockees dans le dossier data de MySQL (exemple courant sous Windows: C:/ProgramData/MySQL/.../Data/sarbi_rohek selon ton installation).

Tomcat et application

Le projet est deploye sous Tomcat dans webapps/sarbi_rohek. Les pages frontend appellent les servlets (par exemple /api/register et /api/login), Tomcat execute ensuite la logique Java.

Comment la connexion est faite

La classe repository charge le driver MySQL puis ouvre les connexions JDBC avec DriverManager (URL, user, password). Les servlets passent par cette couche pour lire et ecrire dans les tables providers et messages.

Pourquoi Tomcat et pourquoi MySQL ?

Pourquoi Tomcat

  • Tomcat est adapte aux applications Java basees sur Servlets/JSP.
  • Il est leger, stable et simple a deployer dans un contexte academique.
  • Il gere nativement les sessions utilisateur, utiles pour login/logout.
  • Il facilite l'exposition d'API comme /api/register et /api/login.

Pourquoi MySQL

  • MySQL est un SGBD relationnel fiable pour stocker comptes et messages.
  • Il est tres compatible avec Java via JDBC et mysql-connector-j.
  • Il permet des requetes SQL claires (SELECT, INSERT, UPDATE, DELETE).
  • Il est facile a administrer localement pour developpement et demo.

Pourquoi ce duo ensemble

Tomcat execute la logique metier Java, et MySQL conserve les donnees persistantes. Cette separation (serveur applicatif + base relationnelle) donne une architecture claire, evolutive et facile a maintenir.
